# Agent Note: TTDS 全局语音总管的设计理念与模块拆分

Status: proposed

## 问题

在 DeepSeek Harness（DSH）中引入实时语音交互时，单纯将语音转写为输入框草稿（如宿主实验性的 `client-ui-voice-input`）外加全文 TTS 朗读，或者直接用端到端语音模型替代 DSH 主 Agent，都会破坏对话体验与工程可靠性：

- **主执行引擎与实时对话的节奏错配**：DSH 主 Agent（如 DeepSeek Reasoner / Chat）面向深度代码分析与多步工具链执行，单轮耗时常达数秒至数分钟，产物是高密度的 Markdown、代码块与 Diff；既无法提供毫秒级话轮反馈，也不适合逐字朗读。
- **实时语音模型的上下文盲区与幻觉风险**：端到端实时语音模型具备极低的首音延迟、打断感知与自然口语韵律，但本身不掌握 DSH 的会话历史、工作区文件与审批状态；若缺乏受确认的工具调用约束，极易凭空编造工作区事实，或出现“口头承诺执行但未实际发起调用”的幻觉。
- **跨会话协作割裂**：用户在 DSH 中往往同时推进多个会话与后台任务，绑定在单一会话上的语音入口在切换视图或新建会话时会中断连接，无法承担全局统筹与异步进度播报。

## 提案

将 TTDS（Talk to DeepSeek）定位为驻留在 DSH 工作台全局层的**拟人化实时语音总管（1:N Global Voice Supervisor）**：将**前台实时交流层**与**后台 DSH 执行层**解耦，以受控的非阻塞异步工具调用（Async Tool Use）和事件钩子（Hooks）连接两侧，使语音总管能够一边陪用户自然口语交谈、一边在后台查看 DSH 内容并协助操作 DSH。

整体系统围绕三个拟人化目标设计，并拆分为四个职责正交的子模块，按模块分别制定详细架构提案；配置界面收敛在 DSH 原生「插件」二级详情页（`plugins.bundle.config`），采用可扩展的多语音提供方（Multi-Provider）选择结构与跨提供方通用的设备、提示词、工具及钩子分区。

## 三大拟人化目标的机制映射

- **低延迟（Low Latency）**：前台采用独立的双向流式语音会话，支持随时打断（Barge-in）、用户手动控制麦克风启停/静音以及直接文字输入互补；不仅后台 DSH 会话任务异步推进，语音总管自身发起的耗时工具调用也采用非阻塞异步执行（边聊边干），工具在后台运行期间完全不阻塞用户继续开口闲聊或追问其它话题。
- **低幻觉（Low Hallucination）**：语音总管对工作区与会话事实执行“零臆测”提示词与工具契约约束；所有关于会话进展、文件改动、待批权限与后台任务的陈述均须取自 DSH 公开接口的真实返回，工具输出须经后端送达确认（Confirmed Delivery）并落盘后再触发或合入续答，且每次会话的生效指令、工具定义、用户文本与语音转写、助手回复（含打断截断态）、工具调用与结果、钩子注入及会话轮换基线均按序写入语音总管专属会话日志（原始声学 PCM 不落盘，日志完整承载结构化文本上下文的审计与恢复重建）；未知或执行中状态如实告知。
- **富有交流感（Conversational Presence）**：执行跨模态信息降维——语音通道只输出符合口语习惯的短句摘要、分歧澄清与决策确认，不朗读文件路径、代码块或原始 JSON；结构化细节留在 DSH 界面同步展示，异步工具结果与后台关键进展在对话空闲时自然接话播报。

## 模块拆分与职责边界

1. **语音运行时适配层（Voice Runtime Adapter，后端）**：定义与具体模型厂商解耦的多提供方注册表与双向实时语音会话契约（音频上下行、文本直输、麦克风静音/启停、打断信号、内部预置提示词与用户自定义提示词合并、非阻塞异步工具回填与能力特征声明 `autoRespondOnToolOutput`），详见[语音运行时适配层提案](2026-11-11-voice-runtime-adapter.md)。首个内置提供方适配阿里云百炼 **Qwen-Audio 3.1 Realtime**（支持 `Qwen-Audio 3.1 Realtime Flash` 与 `Qwen-Audio 3.1 Realtime Plus` 两档型号，默认关闭模型黑盒原生联网搜索），将其专有会话参数与 WebSocket 确认握手封闭在适配器内，并支持后续注册扩展其他实时语音提供方。
2. **DSH 桥接工具注册表（Voice Tool Registry，后端）**：通过 DSH 公开服务（如 `ctx.sessionController`、`ctx.workspaceFiles`、`ctx.workspaceChanges`、`ctx.userQuestions`、`ctx.jobs`、`ctx.web` 及客户端 `ctx.uiSession`）提供 11 个核心查看、联网检索（`dsh_search`）与操作类工具，并开放公开注册接口供扩展，详见[DSH 桥接工具注册表提案](2026-11-11-voice-tool-registry.md)。工具执行采用非阻塞异步派发：后台运行中的工具不阻塞前台新语音或文字轮次，用户中途语音插话打断播报不会误取消后台正在执行的工具；在输出控制上通过 `maxOutputChars`、`drillDownParams` 与 `truncated: true` 实施注册期与运行期双阶段确定性门禁，配合两档调用安全确认（`auto` / `ui`）防止幻觉越权。
3. **事件钩子与话轮礼让缓冲（Event Hook Engine，后端）**：监听 DSH 宿主生命周期事件（顶层会话轮次完成、轮次异常、待处理权限审批、待回答问题与非阻塞后台作业结算），并统一承接 `autoRespondOnToolOutput === false` 模型下异步工具回填后的礼让续答调度，详见[事件钩子与话轮礼让缓冲提案](2026-11-11-event-hook-engine.md)。当用户未插入新对话且会话处于真正静默态时，紧邻当轮完成的快速工具可直通即时续答；一旦期间用户已展开边聊边干或会话非静默，异步工具续答信号与宿主事件钩子统一进入受静默礼让窗口（`quietGraceMs`，默认 `5000` 毫秒）保护的待处理缓冲池——若等待期间用户主动开口追问，模型直接读取已落盘的工具结果自然作答并自动消解待续答信号；若保持静默满礼让窗口，则一次性合并触发单次语音生成，彻底杜绝抢话与并发冲突。
4. **客户端全局舞台与浮层交互（Client UI & Brand Avatar，前端）**：100% 融入 DSH 原生样式且**零改动宿主已有 UI 文案**，只依赖 DSH 公开客户端插槽与 [Web UI 样式参考](../../../../docs/web-styling.md)，详见[客户端全局舞台、浮层胶囊与设置页提案](2026-11-11-client-ui-stage.md)。总管界面柔和极简，不设多余模式切换或会话切换组件，少文字、纯图标融合，所有单行文本压缩时严格按 DSH 默认省略（`ellipsis`）截断：在 `sidebar.panellist` 注册全局入口；在 `main` 注册极简语音舞台，呈现去实心微雾光晕与放大 `FishLogo` 的无外波纹单色四态声波环（`关闭`、`待机`、`倾听`、`说话`）、旁侧无边框渐隐流式事件流与纯图标控制坞；在 `shell.overlay` 注册支持缩成微球、任意位置拖拽及缩进窗口边框露出一半的保活声波胶囊；在 DSH 原生「插件」二级详情页（`plugins.bundle.config`）挂载原生 `<SettingsForm>` 配置骨架。

## 考虑过的替代方案

**单层语音听写加主 Agent 回复全文 TTS 朗读。** 落选原因：DSH 主 Agent 单轮执行耗时长且输出包含大量代码与格式标记，直接串联会导致长静默等待与生硬朗读，无法满足低延迟与交流感目标。

**1:1 绑定单个 DSH 会话的局部语音插件。** 落选原因：用户切换会话、浏览文件或同时运行多个任务时语音连接会被迫中断或失焦，无法作为全局协作者跨会话查询状态与统筹派发指令。

**同步阻塞工具执行，或在工具结果回填后由运行时硬编码无条件立即发送 `response.create`。** 落选原因：同步阻塞会剥夺耗时工具执行期间用户与语音总管“边聊边干”的能力，而无条件立即发送 `response.create` 既与原生自动续答模型不兼容，又会在用户正在说话或组织追问时撞车抢话；通过适配器能力位 `autoRespondOnToolOutput` 解耦并将延迟续答统一并入话轮静默礼让缓冲池，可兼顾快速查询秒回与异步任务礼让接话。

**直接将 Qwen-Audio 3.1 Realtime API 的原始事件字段透传给工具层与前端视图。** 落选原因：会把前端四态声波动画、事件流渲染和工具回填逻辑与单一云端协议锁死，后续接入其他 Realtime 模型或流式级联方案时需要推倒重写。

**靠外层裸字符截断或人工构造大样本单测来约束工具输出，或为繁忙期 Hook 暴露多种排队/丢弃枚举。** 落选原因：裸字符截断会切碎 JSON，单纯靠人工单测无法自动覆盖新增或扩展工具，改为由 `drillDownParams` / `maxOutputChars` 与返回体 `truncated` 字段触发确定性契约校验更可靠；繁忙期统一进入静默礼让窗口缓冲合并，无需增加用户理解负担。

**自创深色卡片风格、修改宿主既有文案、暴露多色状态与模式切换器，或向全局「设置」弹窗额外注入独立分区。** 落选原因：脱离宿主原生 Token 与几何规范会破坏界面整体感，过多文字、跳色与模式切换会造成视觉杂乱；采用单色四态去实心声波、无框渐隐事件流、可贴边半露球⇄胶囊并将配置收敛在原生「插件」二级详情页，能零侵入地融入 DSH。

## 验收标准

- 四个子模块提案（[语音运行时适配层](2026-11-11-voice-runtime-adapter.md)、[DSH 桥接工具注册表](2026-11-11-voice-tool-registry.md)、[事件钩子与话轮礼让缓冲](2026-11-11-event-hook-engine.md)、[客户端全局舞台、浮层胶囊与设置页](2026-11-11-client-ui-stage.md)）均明确对应的 DSH 公开扩展点依赖、资源释放（dispose）边界与可自动化的验证方案，并通过独立架构与 Cordis 生命周期审查及仓库 `pnpm run doc-sync` 门禁。
- 前端模块提案包含原生融合 UI/UX 初稿矢量资产、精确视觉几何参数，以及原生「插件」二级详情页的多提供方连接面板与通用设置完整字段映射。

## 风险

- **双层协作的意图转述失真**：语音总管向后台 DSH 派发任务时，若总结过于简略可能遗漏用户口述的细节约束；需在派发工具参数契约与 `ui` 确认摘要中保留关键原话要点。
- **长连接语音上下文膨胀与注意力退化**：全局常驻的实时语音会话随着多轮边聊边干与 Hook 事件注入，历史上下文会持续累积并增加幻觉概率；由语音运行时适配层的云端轮数滑窗与带版本校验的隔离连接轮换共同约束上下文规模。
- **多模态并发输入竞争**：用户可能在同一时刻既开口说话、又在输入框打字或在 DSH 原生界面点击审批；由运行时适配层的单槽位串行仲裁、工具层的纪元围栏与钩子层的在途复核保障幂等与互斥。
